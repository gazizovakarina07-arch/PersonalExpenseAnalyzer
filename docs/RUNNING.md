# Запуск месячного отчёта

Из корня проекта после сборки Debug:

```powershell
.\out\build\Debug\PersonalExpenseAnalyzer.exe .\data\demo_statement.csv 2026-10
```

Первый аргумент — путь к CSV (путь с пробелами заключить в кавычки),
второй — выбранный месяц `YYYY-MM`. Без аргументов выводится справка.
Windows-версия поддерживает русские пути через `wmain`.

После первого отчёта открывается интерактивное меню. Чтобы вывести отчёт и сразу
завершить программу (например, из скрипта), добавьте третий аргумент `--report`.

## Меню

1. Показать операции выбранного месяца с номерами, счётом, суммой и категорией.
2. Назначить или заменить категорию одной операции. Тип определяется по знаку суммы;
   правило автоматически не создаётся. Номер относится к показанному месячному списку.
3. Создать правило: поиск подстроки либо точное совпадение, текст, категория и тип.
   Правило добавляется в конец и не применяется автоматически.
4. Показать правила в порядке приоритета. Первое совпадение побеждает.
5. Применить правила к операциям без категории выбранного месяца. Уже назначенные
   категории сохраняются. Операции других месяцев этим пунктом не изменяются.
6. Пересчитать и показать месячный отчёт.
0. Завершить сеанс.

Внутри действия `:отмена` возвращает в меню. Неверный ввод выводит сообщение
и возвращает в меню для повторения действия. Конец ввода завершает сеанс.
**Изменения категорий и новые правила существуют только в текущем запуске.**
SQLite пока не подключён, CSV не перезаписывается. При новом запуске импорт и
начальные три правила создаются заново. Период выбирается при запуске и не меняется
в меню. Удаление/перестановка правил и очистка категории пока не предусмотрены.

Программа импортирует весь файл, показывает ошибки с номерами строк,
категоризирует операции и строит отчёт только за выбранные год и месяц.
Расходы показываются положительными суммами, отдельно от доходов.
Разница = доходы минус расходы; это не баланс счёта, поскольку начального
остатка нет. Все счета суммируются вместе, фильтра по счёту пока нет.
Доходы и расходы без категории группируются раздельно, последними в своих разделах.
Отсутствие операций даёт нулевой отчёт. Дубликаты не удаляются.

## Текущие ограничения

- Встроены три демонстрационных правила: описание содержит `Пятерочка` или
  `Аптека` (расходы), либо точно равно `Зачисление зарплаты` (доход).
  Регистр учитывается. Через меню можно добавить правила после них.
- Формат входа описан в `CSV_FORMAT.md`: сумма по-прежнему требует точку
  и две дробные цифры. Вывод на русском использует запятую и пробелы тысяч.
- Расчёты в int64_t копейках с проверками переполнения. Каждый положительный
  итог ограничен INT64_MAX. Операция INT64_MIN допустима для импортёра,
  но отчёт её отклоняет: положительная величина расхода не помещается в int64_t.
  Переполнение приводит к сообщению об ошибке, а не неверному числу.
- Бюджеты, выявление необычных расходов и SQLite ещё не реализованы.

Коды завершения: `0` — полный успех, `1` — ошибка аргументов/файла/расчёта,
`2` — отчёт построен по корректным строкам, но есть ошибки импорта.
При частичном импорте выводится предупреждение о неполноте данных.

## Проверки

```powershell
ctest --test-dir out/build -C Debug --output-on-failure
```

`report_tests` проверяет расчёты, период, неизвестные категории и границы сумм.
`cli_tests` запускает основную программу и проверяет русский вывод, аргументы,
пустой месяц и частичный импорт. Временная выписка создаётся в папке сборки.
`menu_tests` проверяет ручное назначение, оба вида новых правил, обновление отчёта,
границы месяца, восстановление после ошибочного ввода и конец ввода внутри действия.
`cli_tests` также запускает реальный процесс с последовательностью команд меню на русском.
