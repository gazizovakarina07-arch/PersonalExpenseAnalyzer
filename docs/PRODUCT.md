# Personal Expense Analyzer

Версия документа: `v0.1`

## Название

**Personal Expense Analyzer** — локальный анализатор личных расходов.

## Пользователь

Основной пользователь — человек, который хочет анализировать личные доходы и расходы по банковской выписке, контролировать бюджеты и при этом не передавать финансовые данные внешнему сервису.

## Проблема

Банковская выписка содержит много отдельных операций, поэтому вручную распределять их по категориям и подсчитывать расходы неудобно. Встроенная аналитика банка может использовать неподходящие категории и обычно ограничена счетами одного банка. Электронные таблицы позволяют выполнить расчёты, но требуют ручной настройки формул и регулярного обновления. Пользователю нужен простой локальный инструмент, который превращает CSV-выписку в понятный отчёт.

## Текущий способ решения

Пользователь просматривает операции в приложении банка либо переносит их в электронную таблицу. Категории, суммы по месяцам и превышения лимитов он проверяет вручную. Неопознанные операции приходится разбирать отдельно.

## Ценность продукта

Приложение ускоряет обработку банковской выписки, автоматически применяет понятные правила категоризации, показывает структуру расходов и предупреждает о превышении бюджета. Обработка выполняется локально, поэтому демонстрационные или личные финансовые данные не требуется отправлять во внешнее облако.

## Основной пользовательский сценарий

1. Пользователь запускает приложение и выбирает CSV-файл согласованного формата.
2. Система проверяет строки выписки и сообщает о некорректных данных без аварийного завершения.
3. Корректные операции импортируются и распределяются по категориям согласно сохранённым правилам.
4. Операции, для которых правило не найдено, получают статус «Не определено».
5. Пользователь задаёт или изменяет месячные лимиты для категорий.
6. Система формирует месячный отчёт, показывает суммы по категориям, превышения бюджетов и необычно крупные расходы.
7. Необходимые настройки и результаты сохраняются для следующего запуска.

## MVP

Минимальная связная версия продукта включает:

- консольный интерфейс;
- импорт одного документированного формата CSV;
- проверку обязательных полей, даты и суммы операции;
- хранение доходов и расходов в предметной модели;
- категоризацию операций по настраиваемым правилам;
- отдельное отображение неопределённых операций;
- установку месячного бюджета для категории;
- месячный отчёт по категориям и бюджетам;
- выявление необычно крупной операции по явно описанному правилу;
- сохранение необходимых пользовательских данных между запусками;
- обработку ошибочного файла без аварийного завершения;
- автоматические тесты ключевой бизнес-логики.

## Что не входит в MVP

- графический интерфейс Qt;
- поддержка форматов нескольких банков;
- синхронизация с банковскими аккаунтами;
- многопользовательский режим и регистрация;
- мобильное или веб-приложение;
- прогнозирование расходов;
- обязательная зависимость от внешнего или локального ИИ;
- работа с реальными банковскими данными в демонстрационной версии.

## Аналоги и заменители

1. **Электронные таблицы (Excel или Google Sheets).** Гибкие, но требуют ручного импорта, настройки формул и правил.
2. **Аналитика в приложении банка.** Не требует отдельной установки, но обычно ограничена одним банком и не даёт пользователю полностью управлять правилами категоризации.
3. **Облачные приложения для учёта финансов.** Предлагают развитый интерфейс, однако могут требовать регистрацию, подписку или передачу финансовых данных внешнему сервису.


## Критерии готовности MVP

MVP считается готовым, если одновременно выполнены следующие условия:

- проект собирается по инструкции CMake в чистом каталоге сборки;
- приложение успешно импортирует подготовленный демонстрационный CSV-файл;
- некорректная дата, сумма или отсутствующее поле дают понятное сообщение об ошибке и не приводят к аварийному завершению;
- операции распределяются по категориям согласно заданным правилам, а неизвестные остаются неопределёнными;
- пользователь может задать бюджет категории и увидеть его превышение;
- месячный отчёт правильно подсчитывает доходы, расходы и суммы по категориям;
- система отмечает необычно крупные расходы по документированному критерию;
- необходимые данные восстанавливаются после повторного запуска;
- автоматические тесты ключевых правил и хотя бы одного пограничного случая проходят одной командой;
- `README.md`, `CHANGELOG.md`, `AI_LOG.md` и проектная документация соответствуют реализованной версии;
- основной и один ошибочный сценарий можно воспроизвести на демонстрационных данных.
